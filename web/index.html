        Under the Hood

        How It Works

        The Key

        leanSPHINCS is a stateless hash-based signature from the SPHINCS+ family. We follow the EthLib spec with Keccak-256 as the hash. Its security rests on the hash function alone, with no elliptic curves for a quantum computer to attack. The public key is 32 bytes, a signature is 7,740 bytes, and one key can sign 230 times without keeping any state.

        The Wallet

        A factory deploys one small wallet contract per public key, at an address fixed in advance by CREATE2. The wallet's only owner check is a leanSPHINCS signature, which a verifier contract checks on chain for about 82,000 gas. ETC needs no fork for this. The verifier is ordinary contract code.

        The Message

        Your key signs a hash of the chain ID, the wallet address, the wallet's nonce, the recipient, the amount, the calldata and a deadline one hour out. A signature can't be replayed on another chain, against another wallet or a second time.

        The Gas Wallet

        ETC has no account abstraction, so an ordinary account has to submit the call and pay for it. Its ECDSA key is as vulnerable to a quantum computer as any other. Someone who broke it could spend that account's gas money and nothing else, because the wallet only obeys the leanSPHINCS signature.

        Checks in This Page

        Before you send, the page verifies the signature in JavaScript, then asks the deployed verifier with an eth_call, then simulates the whole transaction. On load it checks the chain ID, compares the verifier's code hash with our build and runs EthLib's test vectors through both verifiers.

        What It Costs

        A first send creates the wallet and uses about 395,000 gas. Later sends use about 265,000, plus 25,000 when the recipient is a new account. Most of it pays for the 7,740 bytes of signature in calldata and for verifying it on chain.
